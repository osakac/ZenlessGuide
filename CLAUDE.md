# ZenlessGuide — правила работы

Сайт-гайд по игре Zenless Zone Zero: тир-лист персонажей и подробные гайды по билдам.
Спецификация проекта — [SPEC.md](SPEC.md).

## Рабочий процесс и коммиты

- **Никогда не делать коммит автоматически.** Всегда спрашивать разрешение перед `git commit`.
- **Никогда не указывать со-авторство Claude** в коммитах: никаких `Co-Authored-By: Claude`, никаких упоминаний Claude Code в сообщении коммита.
- Цикл работы: Claude вносит изменения → пользователь делает ревью → правки и повтор итерации при необходимости → после успешного ревью коммит.
- Сообщения коммитов — краткие и смысловые, в стиле Conventional Commits: `feat:`, `fix:`, `refactor:`, `chore:`, `docs:`, `test:`. Язык — русский или английский, но одинаково внутри проекта.

## Архитектура: Feature-Sliced Design

Роутинг Next.js живёт в корневом `app/` и остаётся **тонким**: файл маршрута только загружает данные через `shared/api` и рендерит компонент из `src/views`. Вся логика и UI — в `src/`.

Слои (сверху вниз), `src/`:

| Слой | Назначение |
|---|---|
| `app` | Провайдеры, глобальные стили |
| `views` | Композиция страниц (в терминах FSD это слой `pages`; переименован, т.к. `pages` зарезервировано Next.js) |
| `widgets` | Крупные самостоятельные блоки: `tier-board`, `character-card-grid`, `character-guide`, `header`, `footer` |
| `features` | Пользовательские сценарии: `filter-characters` |
| `entities` | Бизнес-сущности: `character`, `tier` — модели и их отображение |
| `shared` | Без привязки к домену: `ui` (shadcn/ui), `api` (доступ к данным), `lib`, `config` |

Правила:

- Слой импортирует **только нижележащие** слои. Кросс-импорты внутри одного слоя запрещены (кроме `shared`). Это проверяется ESLint (`eslint-plugin-boundaries`) — `npm run lint`.
- Импорт только через публичный API слайса: `@/entities/character`, а не `@/entities/character/ui/CharacterCard`.
- Алиасы: `@/*` → `src/*`, `@data/*` → `data/*`.

## Данные

- Источник данных — `data/characters.json` и `data/tierlist.json`.
- Обращаться к ним **только через `src/shared/api`**. Ни один компонент не импортирует JSON напрямую — это позволит заменить файлы на БД, не трогая UI.
- Все функции `shared/api` асинхронные, даже если сейчас читают JSON синхронно.
- Данные валидируются zod-схемами (`src/shared/api/schemas.ts`); типы выводятся из схем через `z.infer`.
- Реальные данные персонажей добавляются итеративно по мере поступления от пользователя. Поля билд-гайда опциональны — страница должна корректно рендериться с частично заполненными данными.

## Прочее

- Язык интерфейса — русский.
- Компоненты UI ставятся через `npx shadcn@latest add <name>` — алиасы в `components.json` настроены на `src/shared/ui`.
- Перед сдачей работы прогонять: `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`.
