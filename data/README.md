# Данные

Источник данных сайта. Обращаться к файлам только через `src/shared/api` — компоненты не импортируют JSON напрямую.

| Файл | Содержимое |
|---|---|
| `characters.json` | Персонажи: карточка, статы, билд-гайд |
| `tierlist.json` | Список тиров и распределение персонажей по ним |

## Статус наполнения

Заведены **26 агентов** — тиры S (10) и A (16). Фактура (статы 60 уровня, оружие, дисководы, приоритет статов, команды) собрана с [prydwen.gg/zenless](https://www.prydwen.gg/zenless) по состоянию на 2026-09-08. Русские названия, описания и комментарии к билдам написаны для этого проекта.

Остальные агенты добавляются партиями по мере согласования русских названий.

Команды хранятся у каждого персонажа, но собираются из общего пула составов: если состав указан у одного участника, он есть и у остальных двоих. Добавляя состав, вносите его всем троим — иначе со страницы напарника не будет пути обратно.

Изображения — сгенерированные SVG-заглушки в `public/images/characters/`, по одной на персонажа, цвет градиента соответствует стихии.

## Как добавить персонажа

1. Добавить объект в `characters.json`. Обязательны: `id`, `slug`, `name`, `rarity`, `attribute`, `specialty`, `shortDescription`, `image`. Всё, что относится к билд-гайду, опционально — незаполненные блоки просто не отрисуются, как и блок `stats`.
2. Добавить запись в `entries` из `tierlist.json` со ссылкой на тот же `id`. Кроме `tier` обязательна `role` — одно из `dps`, `sub-dps`, `support`: по ней тир-лист раскладывает персонажей на подгруппы внутри тира.
3. Положить изображение в `public/images/characters/` по пути из поля `image`.
4. Ничего в коде править не нужно: страница, карточка и фильтры соберутся сами.

Ключи `attribute`, `specialty`, `rarity` — машинные (`ice`, `attack`, `S`). Русские подписи и цвета для них живут в `src/shared/config` и `src/app/styles/globals.css`. Неизвестный ключ отобразится как есть, но останется без цвета — для новой стихии нужно добавить и подпись, и CSS-переменную.

Поддерживаемые стихии: `physical`, `fire`, `ice`, `electric`, `ether`, `wind`, `lumiflux`.
Специализации: `attack`, `stun`, `anomaly`, `support`, `defense`, `rupture`.

Данные валидируются zod-схемами (`src/shared/api/schemas.ts`) при первом обращении: ошибка в JSON вызовет падение с указанием конкретного поля.
