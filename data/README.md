# Данные

Источник данных сайта. Обращаться к файлам только через `src/shared/api` — компоненты не импортируют JSON напрямую.

| Файл | Содержимое |
|---|---|
| `characters.json` | Персонажи: карточка, статы, билд-гайд |
| `teams.json` | Составы команд: участники по `id` агентов |
| `tierlist.json` | Список тиров и распределение персонажей по ним |

Остальные агенты добавляются партиями по мере согласования русских названий.

Команды вынесены в `teams.json` и заводятся заново: прежние составы, лежавшие внутри `characters.json`, удалены (их можно поднять из истории git). Сейчас заведено пятнадцать составов.

Изображения — карточные портреты в `public/images/characters/<slug>.webp` (374×512). Взяты с prydwen.gg; сама иллюстрация принадлежит HoYoverse. Файлы лежат в репозитории, а не подгружаются с чужого CDN.

Добавление агента с prydwen.gg автоматизировано скиллом `add-new-agent` (`.claude/skills/add-new-agent/`): он собирает фактуру поэтапно, согласует перевод и пишет во все три файла сразу. Порядок ниже описывает то же самое вручную.

## Как добавить персонажа

1. Добавить объект в `characters.json`. Обязательны: `id`, `slug`, `name`, `rarity`, `attribute`, `specialty`, `shortDescription`, `image`. Всё, что относится к билд-гайду, опционально — незаполненные блоки просто не отрисуются, как и блок `stats`.
2. Добавить запись в `entries` из `tierlist.json` со ссылкой на тот же `id`. Кроме `tier` обязательна `role` — одно из `pure-dps`, `anomaly-dps`, `support`: это колонки сетки тир-листа.
3. Положить портрет в `public/images/characters/<slug>.webp` — путь из поля `image`.
4. Добавить составы с его участием в `teams.json` — **по одному разу на состав**, а не каждому участнику.
5. Ничего в коде править не нужно: страница, карточка и фильтры соберутся сами.

Ключи `attribute`, `specialty`, `rarity` — машинные (`ice`, `attack`, `S`). Русские подписи и цвета для них живут в `src/shared/config` и `src/app/styles/globals.css`. Неизвестный ключ отобразится как есть, но останется без цвета — для нового атрибута нужно добавить и подпись, и CSS-переменную.

Поддерживаемые атрибуты: `physical`, `fire`, `ice`, `electric`, `ether`, `wind`, `lumiflux`.
Специализации: `attack`, `stun`, `anomaly`, `support`, `defense`, `rupture`, `armorer`.

Данные валидируются zod-схемами (`src/shared/api/schemas.ts`) при первом обращении: ошибка в JSON вызовет падение с указанием конкретного поля.

## Как добавить команду

Одна запись в `teams.json` = один состав:

```json
{ "members": ["claret", "norma", "rina"], "damageType": "pure-dps" }
```

- `members` — **ровно три разных `id`** агентов (те же id, что в `tierlist.json`). Порядок авторский, основным ДД вперёд, — он сохраняется при отрисовке. Названия и комментария у состава нет: на странице это три портрета.
- `damageType` — необязательное поле, `pure-dps` или `anomaly-dps`: чем состав в целом преимущественно наносит урон. Третьего значения `support` для состава не бывает — команда без ДД не команда. Рисуется бейджем на карточке состава тем же цветом, что и одноимённая колонка тир-листа. Пока не заполнено — бейдж просто не отрисовывается.
- Состав сам появляется на страницах всех трёх участников: принадлежность команды агенту не хранится, а выводится из `members`. Поменяли участника — команда пропала у одного и появилась у другого.
- Два состава с одинаковым набором агентов запрещены; порядок участников на это не влияет.
- Все три агента должны быть уже заведены в `characters.json`: ссылка на неизвестный `id` роняет `npm run build` и `npm run test` с указанием состава и id.
