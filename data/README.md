# Данные

Источник данных сайта. Обращаться к файлам только через `src/shared/api` — компоненты не импортируют JSON напрямую.

| Файл | Содержимое |
|---|---|
| `characters.json` | Персонажи: карточка, статы, билд-гайд |
| `tierlist.json` | Список тиров и распределение персонажей по ним |

## Статус: заглушки

Записи в обоих файлах — **временные плейсхолдеры** для разработки каркаса. Имена персонажей настоящие, но статы, оружие, диски и распределение по тирам придуманы и **не отражают актуальную мету**. Их заменит реальная информация по мере поступления.

Изображения — сгенерированные SVG-заглушки в `public/images/characters/`.

## Как добавить персонажа

1. Добавить объект в `characters.json`. Обязательны: `id`, `slug`, `name`, `rarity`, `attribute`, `specialty`, `weaponType`, `shortDescription`, `image`. Всё, что относится к билд-гайду, опционально — незаполненные блоки просто не отрисуются.
2. Добавить запись в `entries` из `tierlist.json` со ссылкой на тот же `id`.
3. Ничего в коде править не нужно: страница, карточка и фильтры соберутся сами.

Ключи `attribute`, `specialty`, `weaponType`, `rarity` — машинные (`ice`, `attack`, `slash`, `S`). Русские подписи и цвета для них живут в `src/shared/config`. Неизвестный ключ отобразится как есть.

Данные валидируются zod-схемами (`src/shared/api/schemas.ts`) при первом обращении: ошибка в JSON вызовет падение с указанием конкретного поля.
