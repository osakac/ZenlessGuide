# Спецификация: сайт-гайд по Zenless Zone Zero

> Версия 0.2 — черновая спецификация. Реальные данные персонажей будут добавляться отдельно, по указаниям пользователя.

## 1. Обзор проекта

Сайт-гайд по игре **Zenless Zone Zero (ZZZ)**. Две основные функции:

1. **Тир-лист персонажей** — рейтинг силы персонажей по тирам.
2. **Гайды по персонажам** — подробная информация по каждому персонажу (роль, статы, рекомендуемые билды, синергии).

Целевая аудитория — игроки ZZZ, которые хотят понять, каких персонажей качать и как их билдить.

## 2. Технологический стек

| Слой | Выбор |
|---|---|
| Фреймворк | Next.js (App Router) + TypeScript |
| Архитектура фронтенда | Feature-Sliced Design (FSD) — строго соблюдается, см. раздел 3 |
| UI-библиотека компонентов | shadcn/ui (Radix UI + Tailwind CSS) |
| Стилизация | Tailwind CSS |
| Данные | Локальные JSON-файлы (`/data/characters.json`, `/data/teams.json`, `/data/tierlist.json`) |
| Деплой | Не зафиксирован; напрашивается Vercel (стандарт для Next.js) |

**Важно:** доступ к данным инкапсулируется в отдельном модуле уровня `shared` (см. FSD ниже), а не разбросан по компонентам напрямую. Это позволит в будущем заменить JSON-файлы на настоящую БД (Postgres/SQLite + ORM), не переписывая страницы и компоненты.

## 3. Архитектура: Feature-Sliced Design (FSD)

Фронтенд строго следует методологии FSD. Next.js App Router используется только как роутинг-обвязка (папка `app/`), вся бизнес-логика и UI живут в `src/`, слоями сверху вниз:

| Слой | Назначение в проекте |
|---|---|
| `app` (FSD) | Провайдеры, глобальные стили, инициализация — переиспользуется из корневого `app/layout.tsx` |
| `pages` (FSD) | Композиция страниц: `pages/home`, `pages/tierlist`, `pages/character-list`, `pages/character-details` — каждая собирается из виджетов/фич нижних слоёв |
| `widgets` | Крупные самостоятельные блоки: `widgets/tier-board` (доска тир-листа), `widgets/character-card-grid`, `widgets/character-guide` |
| `features` | Пользовательские сценарии: `features/filter-characters`, `features/filter-tierlist` и т.п. |
| `entities` | Бизнес-сущности и их отображение: `entities/character` (модель `Character`, карточка персонажа), `entities/tier` (модель `TierEntry`, бейдж тира) |
| `shared` | Переиспользуемое без привязки к домену: `shared/ui` (обёртки над shadcn/ui компонентами), `shared/api` (доступ к JSON-данным), `shared/lib`, `shared/config` |

Правила импортов — стандартные для FSD: слой может импортировать только нижележащие слои, кросс-импорты внутри одного слоя запрещены (кроме `shared`). Файлы маршрутов Next.js (`app/tierlist/page.tsx` и т.д.) — тонкие, только рендерят соответствующий слой `pages`.

## 4. Структура сайта

| Маршрут | Назначение |
|---|---|
| `/` | Главная — краткое описание сайта, ссылки на тир-лист и список персонажей |
| `/tierlist` | Тир-лист — персонажи по тирам (S/A), внутри тира разбиты на основных ДД, саб-ДД и поддержку; фильтры по стихии, специализации и рангу |
| `/characters` | Список всех персонажей карточками, с переходом на страницу гайда |
| `/characters/[slug]` | Страница персонажа — статы, роль, билд-гайд, синергии с командой, место в тир-листе |

## 5. Черновая модель данных

Не финальная — уточнится, когда пойдут реальные данные. Поля намеренно оставлены расширяемыми.

```ts
type Character = {
  id: string;
  slug: string;
  name: string;
  rarity: string;        // например, S / A
  attribute: string;     // стихия: электро, огонь, лёд и т.д.
  specialty: string;     // роль: Атака, Защита, Support, Стан и т.д.
  shortDescription: string;
  image: string;         // путь к изображению/иконке
  // билд-гайд — набор полей уточним при первой партии данных
  buildGuide?: Record<string, unknown>;
};

type TierEntry = {
  characterId: string;
  tier: string;                          // S / A
  role: "pure-dps" | "anomaly-dps" | "support"; // колонка в сетке тир-листа
};

// Команда — отдельная запись, а не поле агента: связь выводится из состава,
// поэтому один состав показывается на страницах всех трёх участников.
type Team = {
  name: string;
  members: [string, string, string]; // id агентов, отряд всегда из троих
  note?: string;
};
```

## 6. Не входит в текущий объём (Non-goals)

- Наполнение реальными данными персонажей — отдельный этап, по мере того как пользователь будет присылать данные
- Полноценная БД / бэкенд API
